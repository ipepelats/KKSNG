# Конспект проекта: ККСНГ_Курьер (СберКорус ЭДО)

## 📌 Описание проекта
**ККСНГ_Курьер** — это расширение для 1С (версия 0.57.2119), разработанное ООО «СберКорус». 
Оно работает как «почтовый ящик» внутри 1С: позволяет отправлять, получать и подписывать электронные документы (УПД, акты, счета), не заходя на сайт оператора ЭДО (Сфера Документы).

**Аналогия:** Это как встроенный клиент электронной почты, который сам умеет запаковывать письма по стандарту налоговой (ФНС) и ставить на них электронную сургучную печать (ЭЦП).

---

## 🛠 Техническая база
*   **Платформа:** 1С:Предприятие 8.3 (режим совместимости 8.3.12).
*   **Конфигурация пользователя:** Бухгалтерия предприятия 3.0.
*   **Связь с сервером (API):** Обмен идет по протоколу HTTP(S) в формате JSON (иногда XML) через `courier-api.esphere.ru`.
*   **Авторизация:** Через API-ключ или Токен Сбербанка (VPNKey-TLS / Рутокен). В запросах используется заголовок `Auth-Token`.

---

## 📦 Архитектура расширения
Расширение содержит множество штатных объектов 1С:
*   **Справочники:** `ККСНГ_Организации`, `ККСНГ_Контрагенты`, `ККСНГ_ЭлектронныеДокументы`.
*   **Общие модули:** Начинаются с префикса `ККСНГ_`. Ключевые для обмена: 
    *   `ККСНГ_APIКурьер` — работа с методами API.
    *   `ККСНГ_ОтправкаЭДВызовСервера` / `ККСНГ_ОтправкаЭДКлиент` — логика отправки.
    *   `ККСНГ_ФормированиеXML` — генерация файлов по форматам ФНС (например, 5.03 для УПД).
*   **Регистры:** Хранение настроек, подписок на события (`ККСНГ_СобытияПодписок`), приглашений.
*   **XDTO-пакеты:** Для сериализации данных (например, `ККСНГ_KorusEdsApi`).

---

## 🔌 Особенности API СберКорус
1.  **Форматы:** УПД формируется в строгом XML (формат 5.03). Неформализованные документы (PDF, Word) уходят в Base64.
2.  **Роуминг:** Большинство контрагентов сидят у других операторов. Перед отправкой система ищет `ИдУчЭДО` (Идентификатор участника ЭДО) и проверяет активную взаимосвязь.
3.  **Пакеты (Batch / Package):** API позволяет отправлять несколько документов вместе.
    *   `POST /api/document/addBatch` с флагом `"CreatePackage": true` — создает пакет сразу.
    *   `POST /v2.0/package` — объединяет уже созданные черновики в пакет.

## 🎯 Текущая задача (Техническое задание)
**Цель:** Автоматизировать отправку Счета на оплату вместе с УПД.

**Как это должно работать:**
1.  Пользователь в 1С отправляет УПД (или счет-фактуру) по документу Реализации.
2.  Система должна проверить, привязан ли к этой Реализации «Счет покупателю».
3.  Если счет есть, система берет его печатную форму (тип файла свободный).
4.  Счет и УПД объединяются в **один пакет** («скрепляются степлером»).
5.  Весь пакет подписывается ЭЦП и отправляется контрагенту.

**Сложность:** Контрагенты в роуминге. Пакет должен корректно дойти через роуминг-шлюз.

---

## 📝 План действий для разработчика
1.  Найти в 1С место формирования отправки УПД (скорее всего, в обработке `ККСНГ_СфераКурьер` или модулях `ККСНГ_ОтправкаЭД*`).
2.  Добавить алгоритм поиска связанного документа «Счет на оплату» на основании документа-источника.
3.  Сформировать файл счета (например, PDF в Base64).
4.  Перестроить вызов API: вместо отправки одного документа (`add`) использовать метод групповой отправки (`addBatch` с `CreatePackage = true`) или связывать их через метод `/v2.0/package`.
5.  *(Важно)* Использовать только штатные методы 1С (никаких придуманных функций).
