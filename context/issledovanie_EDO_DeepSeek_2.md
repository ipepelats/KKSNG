### 1️⃣ Работа с API СберКорус

СберКорус предоставляет `REST API` для интеграции, документацию по которому можно найти на портале для разработчиков Сбера.

**Ключевые моменты для разработчика:**

*   **Аутентификация**: Стандартная процедура для API Сбера — получение токена доступа с помощью `client_id` и `client_secret`.
*   **Основные методы API**:
    *   `POST /documents` — отправка документа или пакета.
    *   `GET /documents/{id}` — получение статуса и содержимого документа.
    *   `POST /documents/{id}/sign` — подписание документа.
    *   `GET /counterparties` — получение списка контрагентов и их статуса для роуминга.
*   **SDK и библиотеки**: СберКорус может предоставлять SDK для упрощения работы с подписью и шифрованием. **Настоятельно рекомендую** запросить у менеджера или в службе поддержки СберКорус:
    *   Актуальную документацию по API для ЭДО.
    *   SDK (например, на C#, Java, Python) для интеграции.
    *   Тестовую среду (песочницу) для отладки.

> ⚠️ **Важно**: Публичная документация по API СберКорус на данный момент крайне ограничена. Без получения официальных материалов от вендора разработка будет затруднена. Это **критический шаг** перед началом работ.

### 2️⃣ Основной документ: УПД формата 5.03

С 1 апреля 2025 года для электронного документооборота обязателен к использованию формат УПД версии **5.03**. Старые форматы (5.01, 5.02) больше не принимаются.

**Нормативная база**:

*   **Формат утверждён**: Приказом ФНС России от 19.12.2023 № ЕД-7-26/970@.
*   **XSD-схема**: Официальная схема доступна на сайте ФНС: `https://www.nalog.gov.ru/html/sites/www.new.nalog.ru/xsd/...`.

**Действия для разработчика**:

1.  **Скачать XSD-схему УПД 5.03** с сайта ФНС или с ресурсов, предоставляющих актуальные схемы (например, bi-cons.ru или diadoc.ru).
2.  **Изучить структуру XML**, которая включает:
    *   Титул продавца (обязательная часть).
    *   Титул покупателя (для подписания).
    *   Данные о товарах, работах, услугах (табличная часть).
    *   Сведения о подписантах.
3.  **Реализовать генерацию XML** в соответствии со схемой. **Рекомендуется** использовать библиотеки для сериализации/десериализации XML (например, `XmlSerializer` в .NET, `JAXB` в Java), чтобы минимизировать ошибки.
4.  **Обеспечить валидацию** сгенерированного XML по XSD-схеме перед отправкой. Это **обязательное требование** для прохождения форматно-логического контроля (ФЛК) на стороне оператора.

### 3️⃣ Формирование пакета документов

Пакетная отправка позволяет сгруппировать УПД и дополнительные документы (например, PDF-спецификацию, договор, акт) в один контейнер.

**Основные принципы**:

*   **Структура пакета**: Транспортный контейнер (обычно ZIP-архив) содержит:
    *   **Файл метаданных (`metadata.xml`)**: Описывает каждый вложенный документ (тип, имя, MIME-тип, признаки сжатия и шифрования).
    *   **Файлы документов**: `УПД.xml`, `Спецификация.pdf`, `Договор.docx` и т.д.
*   **Правила формирования пакета**:
    *   Основным документом в вашем случае будет УПД (тип `УПД` или `СчетФактура`).
    *   Дополнительные документы имеют тип `Неформализованный` с указанием правильного MIME-типа (например, `application/pdf`).
    *   Важно корректно указать атрибуты `идентификаторДокумента` и `типСодержимого` для каждого документа в `metadata.xml`.
*   **Типы пакетов**:
    *   **Закрытый пакет**: Получатель подписывает или отклоняет весь пакет целиком. Это упрощает обработку, если все документы в пакете тесно связаны.
    *   **Открытый пакет**: Получатель может подписать или отклонить каждый документ по отдельности.

**Действия для разработчика**:

1.  **Разработать генератор `metadata.xml`**, который будет создавать корректное описание пакета на основе переданных файлов.
2.  **Реализовать упаковку файлов в ZIP-архив** с соблюдением структуры, ожидаемой API СберКорус.
3.  **Обратите внимание на ограничения**:
    *   Максимальный размер пакета — обычно **70 МБ**.
    *   Максимальное количество документов в пакете — **до 30**.
    *   В одном пакете не может быть более одного счёта-фактуры (УПД).

### 4️⃣ Подписание документов

Для придания пакету юридической значимости необходимо подписать каждый документ, требующий подписи.

**Варианты подписания**:

*   **Единая подпись для пакета**: Отправитель подписывает весь ZIP-архив одной УКЭП. Это упрощает процесс, но получатель также должен будет подписать пакет целиком.
*   **Раздельное подписание**: Каждый документ в пакете подписывается отдельно (как формализованный УПД, так и неформализованные PDF-файлы). Это даёт больше гибкости, но требует более сложной логики.

**Рекомендация для вашего сценария**: Поскольку вы планируете подписывать и УПД, и дополнительные документы, **рекомендуется использовать раздельное подписание**. Это позволит получателю подписать только УПД и, например, отклонить спецификацию, если в ней обнаружены ошибки.

**Действия для разработчика**:

1.  **Интегрировать библиотеки для работы с УКЭП** (например, КриптоПро CSP, Signal-COM). Эти библиотеки предоставляют API для подписания данных.
2.  **Реализовать подписание для формализованного УПД**:
    *   Подпись встраивается в сам XML-файл в элемент `ЭП` (электронная подпись).
    *   Формат подписи — `XAdES` (XML Advanced Electronic Signatures).
3.  **Реализовать подписание для неформализованных документов**:
    *   Для каждого файла (например, PDF) формируется отдельный файл подписи в формате `PKCS#7` или `CMS`.
    *   Подпись может быть либо встроена в сам файл (для PDF это возможно), либо передана отдельным файлом (`.sig`).
4.  **Включить подписи в пакет** и правильно отразить их в `metadata.xml`.

### 5️⃣ Интеграция с 1С через расширение Сбер ЭДО

СберКорус предоставляет **модуль для 1С "Универсальный"**, который интегрируется с сервисами "Сфера Торговля" и "Сфера Документы". Это готовое решение, которое значительно упрощает задачу.

**Основные возможности модуля**:

*   **Работа в привычном интерфейсе 1С**: Пользователи могут создавать, отправлять и получать документы ЭДО, не покидая 1С.
*   **Автоматический обмен**: Модуль может по расписанию обмениваться документами с сервером СберКорус.
*   **Поддержка пакетной отправки**: Можно отправить комплект документов одной кнопкой.
*   **Контроль статусов**: Модуль отслеживает статусы отправленных/полученных документов (отправлен, доставлен, подписан, отказ).

**Действия для разработчика**:

1.  **Связаться со СберКорус** для получения модуля "Универсальный" для 1С и документации по его установке и настройке.
2.  **Изучить возможности API модуля**: Возможно, он предоставляет свои собственные методы, которые можно вызывать из кода 1С.
3.  **Проверить совместимость** модуля с вашей версией платформы 1С и конфигурацией (например, Бухгалтерия предприятия, Управление торговлей, ERP).
4.  **Разработать, при необходимости, дополнительную обработку**, которая будет:
    *   Собирать данные из документов 1С для формирования УПД (например, из "Реализации товаров и услуг").
    *   Прикреплять дополнительные файлы (печатные формы, спецификации).
    *   Инициировать отправку пакета через модуль "Универсальный".
    *   Обрабатывать входящие подписи и обновлять статусы в 1С.

> 💡 **Совет**: Если функционала модуля недостаточно, можно рассмотреть прямую интеграцию 1С с API СберКорус с помощью HTTP-запросов (REST). Это даст полный контроль, но потребует больше усилий.

### 6️⃣ Роуминг с контрагентами (СБИС, Диадок, Калуга Астрал)

СберКорус поддерживает роуминг с большинством крупных операторов ЭДО, включая СБИС (Тензор), Диадок (Контур) и Калуга Астрал. Роуминг позволяет вашим контрагентам получать и подписывать документы в привычных им системах.

**Как это работает**:

1.  **Приглашение**: Вы (или ваш контрагент) отправляете приглашение к обмену через своего оператора. Для этого обычно требуется знать ИНН и КПП контрагента, а также выбрать его оператора из списка.
2.  **Принятие приглашения**: Контрагент принимает приглашение в своём личном кабинете.
3.  **Обмен**: После активации роуминга все документы, отправленные вами через СберКорус, будут автоматически маршрутизироваться оператору контрагента и доставляться в его ящик.

**Действия для разработчика**:

*   **В рамках модуля "Универсальный"** для 1С настройка роуминга, скорее всего, выполняется через интерфейс модуля или личный кабинет СберКорус.
*   **При прямой работе с API** вам потребуется реализовать методы:
    *   `GET /counterparties` — для поиска контрагентов.
    *   `POST /invitations` — для отправки приглашения.
    *   `GET /invitations/status` — для проверки статуса приглашения.
*   **Важно**: Убедитесь, что используемые вами форматы документов (особенно УПД 5.03) поддерживаются операторами контрагентов. Это критически важно для успешного роуминга.
