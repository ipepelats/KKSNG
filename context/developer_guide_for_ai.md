# Руководство разработчика (AI Agent Guide) по доработке расширения ККСНГ_Курьер

## Цель доработки
Реализовать автоматическое прикрепление "Счета на оплату" к УПД/Счету-фактуре при отправке через ЭДО СберКорус. Документы должны быть объединены в **пакет** (Package/Batch). Контрагенты находятся в роуминге.

**Критическое правило от пользователя:** НЕ придумывать несуществующие методы, использовать ТОЛЬКО существующие методы 1С и расширения.

---

## Точки входа и архитектура кода

### 1. Подготовка и отправка документов (Сервер / Клиент)
Пользователь инициирует отправку из формы или обработки.
*   **Обработка `ККСНГ_СфераКурьер`**: Форма `ОтправкаФайлов`. При нажатии кнопки отправки вызывается логика на клиенте и сервере.
*   **Модуль `ККСНГ_ОтправкаЭДКлиент`**: Метод `ПодписатьИОтправитьЭлектронныеДокументы`. Выполняет валидацию и подписание.
*   **Модуль `ККСНГ_ЭлектронныеДокументыВызовСервера`**: Метод `ОтправитьДанныеПакетовФайловПолучателям`. Основной метод формирования пакета данных для отправки и отправки получателям (строка 364+). Внутри вызываются процедуры:
    *   `ДобавитьВПакетДанныхФайлов(...)`
    *   `ДобавитьПодписиВПакетДанныхФайлов(...)`

> **Где кодить:** Логику поиска связанного «Счета на оплату» на основании документа-источника (Реализации) следует внедрять на этапе сбора "ДанныхКОтправке" (обычно перед вызовом серверных функций отправки или внутри `ПолучитьДанныеПакетовФайловПоДокументам`). Печатная форма счета (PDF/Excel) должна кодироваться в Base64.

### 2. Взаимодействие с API СберКорус (HTTP и XDTO)
Абсолютно все вызовы к API Сферы (courier-api.esphere.ru) инкапсулированы в модуле **`ККСНГ_APIКурьер`**.
*   **Внимание!** В текущей версии расширения (0.57.2119) *нет* готовых оберток-функций с именами `v2_Package` или `v1_addBatch`.
*   Однако в XDTO-пакете `ККСНГ_KorusEdsApi` есть свойства `PackageId`, `PackageRouteSync` и т.д.
*   Отправка одиночного документа происходит через `/api/document/add/{id}` или `/api/document/addAttachment/{id}`.

> **Как реализовать пакет без создания новых оберток API:**
> 1. Если API поддерживает передачу флагов пакетирования внутри структуры самого документа (через поля свойств, например `PackageId`), используйте существующий метод отправки, предварительно заполнив нужные XDTO поля.
> 2. Либо, если пакетность допустимо реализовать как "Вложение" к основному документу (УПД), используйте метод API `ККСНГ_APIКурьер.v1_DocumentAddAttachment(ПараметрыАвторизации, id, FileContent)` — он официально существует в модуле (строка 1916).
> 3. Если необходимо вызвать метод `/v2.0/package`, которого нет в `ККСНГ_APIКурьер`, **НЕ ПИШИТЕ ЕГО С НУЛЯ**. Вместо этого посмотрите, как формируется `СтруктураЗапроса` в модуле `ККСНГ_APIКурьер` и используйте внутреннюю функцию модуля для отправки кастомного запроса, либо аккуратно добавьте новую функцию в модуль строго по аналогии с соседними методами (согласовав с пользователем допустимость такого шага).

### 3. Работа с роумингом
Согласно ТЗ, контрагенты работают через других операторов ЭДО.
*   При отправке документов в роуминг обязательно требуется указать `ИдУчЭДО` получателя (`receiverCode`).
*   Этот код получается штатным методом `ККСНГ_APIКурьер.v2_СlientEdiCode` или `v2_СlientEdiCodes`. Не меняйте логику работы с роумингом, она уже реализована в типовых процедурах отправки. Ваша задача — лишь добавить второй файл к отправляемому УПД.

## План разработки для AI Agent

1.  **Исследовать `ККСНГ_ОтправкаЭДВызовСервера`**: Найдите место, где формируется массив файлов к отправке для выбранного документа "Реализация".
2.  **Добавить извлечение печатной формы**: Напишите типовой код 1С для получения печатной формы "Счета покупателю" по ссылке из документа реализации (используя штатные менеджеры печати БП 3.0). Сохраните в PDF и переведите в Base64.
3.  **Изучить структуру отправки**: Откройте `ККСНГ_ЭлектронныеДокументыВызовСервера` (строки 1062, 1085: `ДобавитьВПакетДанныхФайлов`). Посмотрите, как файлы помещаются в коллекцию для API.
4.  **Модификация API-вызова**: Определите, будет ли Счет отправлен как `addAttachment` к ID основного УПД (что уже поддерживается APIКурьер), либо как отдельный документ с общим `PackageId`.
5.  **Применить изменения**: Внести изменения строго используя паттерны 1С (без выдуманных функций).
